# 16 – Releases, Decisions and Non-Goals

Replacement: part of the content of `../PLANT-SYSTEM-SPECS/12-Target-Architecture-AI-first.md` (principles, technology draft, phases). There the architecture assumed that the **vault stays the source of truth** (ADR-01) and a "hub" holds only the social part. That no longer applies. The technology draft below is the **revised version** for the web app and remains a proposal until the decisions E-01 to E-04 are made.

## Release cut

Principle: every release is **usable** for the three start users. Order by "what is needed to replace the vault?", then social, then engagement.

| Release                       | Content                                                                                                                                                                                           | Epics                                        | Goal                                                                      |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------- |
| **R0 Foundation**             | Accounts, invitation access, locations/light zones, species catalog, specimens                                                                                                                    | ACC, BES, LIC (05)                           | The three can create and view locations, species and specimens in the app |
| **R1 Parity**                 | Phases, measuring with photo, trend/etiolation, treatments, wishlist, Pokédex (cards, ownership, rank, milestones), "Today" list, PWA, accessibility (keyboard, guidance, announcements, display) | PHA, WAC, BEH, WUN, POK, LIC, QS (07–10, 12) | Everything the vault can do today is in the app; switching is possible    |
| **R2 Social**                 | Friends, sharing, feed "New among friends", compare collection, keyboard shortcuts                                                                                                                | SOZ (01–07), QS-11                           | New acquisitions of friends visible                                       |
| **R3 Swapping and reminders** | Offers, swap exchange, handover, notifications, watering log                                                                                                                                      | SOZ (08–13), MON (01–05, 08), ENT (01–07)    | First real swap; engagement through reminders and Discover                |
| **R4 AI access**              | Open interface for AI clients, connections and rights, tasks from the app, drafts, care by voice, daily status, species profile, photo assessment, research                                       | KI                                           | Input without forms via the own AI client; catalog grows                  |
| **R5 Equipment**              | Equipment, light zone binding, need, then recommendations                                                                                                                                         | EQU                                          | Basis for stage 2                                                         |
| **R6 Sensors**                | Sensor pilot, climate, aggregates                                                                                                                                                                 | MON (06, 07)                                 | later, after the hardware decision                                        |

Note: R4 (AI access) deliberately comes **after** R1 to R3. The AI access eases input but is not a precondition for replacing the vault (FR-KI-05). Because it only releases the operations of the domain logic and runs no AI product, the **core** (US-KI-07 connect, US-KI-06 limits, US-KI-10 log, US-KI-01/-02) is small and can be brought forward from R1 as soon as the operations are stable. Tasks and drafts (US-KI-08/-09, US-KI-03) stay R4; the catalog benefits from them early.

Note: ENT (Discover) needs only R1 (catalog, Pokédex, wishlist, measurements) and no friends; it can also come directly after R1. The species attributes (DM-ENT-01) grow with the catalog, AI-supported from R4 (US-ENT-08). Without attributes the shares for space, Pokédex, proximity and preferences already work.

## Technology draft (proposal, not yet decided)

Justified technology-neutrally; specifics are in the decisions.

| Area                | Proposal                                                                                                                                                                                                                                                                              | Reasoning                                                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Language            | TypeScript throughout                                                                                                                                                                                                                                                                 | One language for domain logic, API and web. The prototype logic (`pokedex-core.js`, `finanz-core.js`) is already JavaScript and can be taken over. |
| Structure           | Domain logic as its own package **without I/O**, API, web, later AI layer; monorepo; **modulith** (E-20): one deployable, domain modules with a public interface                                                                                                                      | P-02: one core, many interfaces.                                                                                                                   |
| Data storage        | PostgreSQL, self-operated; tenant isolation by account id and row-level rules that apply via a **session variable per transaction** (account id), not via a provider-specific concept. Access only via the API and the operations layer, never directly from the browser              | P-04. The domain is relational (specimen → measurement, friendship, swap). Runs on any PostgreSQL.                                                 |
| Storage abstraction | Domain logic accesses via repository interfaces                                                                                                                                                                                                                                       | exchangeable storage, testable without a database                                                                                                  |
| Hosting             | Self-operation on own hardware (self-hosted) with Docker (Compose), no Kubernetes. A rented provider is **deferred** and re-evaluated before opening to externals (stage 2); Docker keeps the switch simple                                                                           | Keep operation simple (R-01); no third-party subscriptions for database and sign-in; no rental costs in stage 1                                    |
| Web                 | Mobile-first PWA; **proposal React** (Vite, PWA) as a client of the own API, without server-side rendering (application behind sign-in). Team experience: Angular and React, some Next. Angular would be equivalent                                                                   | P-11: photo, measuring and watering on the phone; native app only on proven need                                                                   |
| Sign-in             | Self-hosted, established OAuth/OIDC server (candidates Keycloak, Zitadel; choice after spike TE-15), at the same time authorization server for AI connections (E-03, FR-KI-13); not built ourselves                                                                                   | NFR-10                                                                                                                                             |
| Media               | Object storage; shrinking and EXIF/GPS removal server-side                                                                                                                                                                                                                            | takes over `foto_import.py`                                                                                                                        |
| AI                  | No built-in AI. Open interface for the keeper's AI clients (proposal: MCP server) as a thin adapter over the validating operations; sign-in per user with rights, server-enforced drafts, rate limits, log                                                                            | KI-R1, KI-R7, KI-R8                                                                                                                                |
| Jobs                | Queue on PostgreSQL (no additional service) for reminders, catalog build, photo processing                                                                                                                                                                                            | simple operation (R-01)                                                                                                                            |
| Push                | Web push; Telegram optional                                                                                                                                                                                                                                                           | replaces the planned bot                                                                                                                           |
| Pokédex build       | Python script of the prototype (73 tests) stays as an **isolated job** with the contract AB-4 (writes only the tree store). The logic `pokedex-core.js` (66 tests) goes to `core`. Port to TypeScript later, secured by comparison with the output of the Python script (golden file) | E-01                                                                                                                                               |
| Tests               | Unit tests of the domain logic, end-to-end tests for core flows; acceptance criteria as tests                                                                                                                                                                                         | P-06                                                                                                                                               |

Deliberately not chosen (proposals of the earlier sketch, still alternatives): PocketBase (fastest prototype, scales worse), local-first sync (only if offline operation becomes a hard must).

The binding quality barriers for this draft (hooks, CI, structure rules, architecture boundaries, privacy gates, definition of done) are in `18-Architecture-and-Quality-Gates.md`. Further decisions E-13 to E-18 there.

## Non-goals (deliberately not in the product)

Automatic watering, photo-based height/moisture estimation, leaderboards and rank comparisons between friends (facts yes, rating no), cultivar slots in the catalog, chat between friends, public profiles, selling for money in stages 1–2, shipping handling, groups, evaluations across many users without a minimum count and displayed sample size, financial management (stays in the vault), built-in AI with operator quota (see E-19).
